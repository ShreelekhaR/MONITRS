MONITRS v2

Multi-image Satellite VQA for Natural Disasters

9,838 events 50K Sentinel-2 images 70,911 QA pairs 17 disaster types

Rebuild of v1 (2023-2024) → v2 (2026): new SDKs, better geolocation, factual captions, cleaner QA

What broke in v1

  • Google Search API deprecated → article scraping fell over
  • google.generativeai SDK sunsetting → we can't use the Gemini calls anymore
  • LLM-only geolocation was unreliable → some events centered hundreds of km off
  • Speculative captions ("satellite would show…") → not learnable, model learned to hedge
  • Broken pixel geo→pixel math (used width/360°) → all locations mapped to image center (256, 256)
  • Slow image downloads (~30s/event, serial per-date) → prohibitive at 10K events
Goal: rebuild the pipeline so a) it runs, b) it produces factual grounded data, c) fits on one A100 for LoRA finetuning of a modern VLM.

QA quality iterations

Three versions of the same open-ended question. We went from speculative → image-analysis-pretending → fact-extraction-from-captions.

Bad: speculative (v1-style)

Q: Can satellite imagery detect physical damage from Hurricane Ida?

A: High-resolution satellite imagery can detect roof damage, collapsed structures, and debris accumulation in residential and commercial areas…

Hedge words. Model can't verify from image. Not learnable.

Interim: Gemini pretends to look at images

Q: What visual evidence indicates the Road 702 Fire reached the Republican River?

A: A dark burn scar is visibly abutting the Republican River. This visual evidence confirms the fire's progression…

Better, but Gemini is inventing visual descriptions it can't actually see. Training on this teaches the model to fabricate too.

Final: facts from captions, no image interpretation

Q: How did the burn scar evolve between July 23 and August 2, 2022?

A: The burn scar became more pronounced and larger, eventually covering approximately 6,735 acres north of FM205 by August 2.

Facts extracted from article captions. Gemini never sees the images. The model learns caption facts ↔ satellite image mapping.

The key insight

Gemini doesn't know what disasters look like in satellite imagery. Neither does the base Qwen2.5-VL. So we can't ask Gemini to describe images — we ask it to convert article facts into Q&A pairs. The trained model then learns to associate those facts with the pixel patterns.

Old approach

Prompt Gemini: "Look at these images, describe what you see."

Result: Gemini hallucinates plausible-sounding descriptions. They don't match the actual image content. Model learns nothing useful.

New approach

Prompt Gemini: "Here are facts from news articles. Convert them into questions and answers, using only the given facts."

Result: Every answer is grounded in a real article statement. During finetuning, the model learns which satellite patterns co-occur with each fact.

Location grounding: multiple dead-ends

  1. Broken geo→pixel math. Old code did (lon × width/360) — collapsed everything to (256, 256). Fixed with proper Sentinel-2 10m GSD projection at bbox latitude.
  2. Public geocoder rate-limited. geocode.maps.co hits limits at 1/sec; also wrong for many small US places ("Cambridge, Nebraska" → Cambridge, UK).
  3. OSM Overpass API blocked from GCP. Rich features available locally, but the workbench IP gets throttled/refused after a few requests.
  4. Local Nominatim, in-house instance. No rate limits, state-hint queries, exact-match on US places. This works.
Result: 760 of 9,838 events have at least one article location that geocodes inside its bbox. That gives us 237 location_identification questions — small n, but real coordinates.

Finetuning setup

Model

  • Qwen2.5-VL-7B-Instruct
  • Native multi-image / variable-resolution VLM
  • Modern replacement for VideoLLaVA

Adapter

  • LoRA rank 16, α 32, dropout 0.05
  • Target: all linear layers in text tower
  • Vision tower frozen
  • ~40M trainable / 8.3B total (0.5%)

Data

  • Train: 20K samples (stratified across 5 tasks)
  • Test: 13,937 samples (untouched during training)
  • Full image sequences per sample
  • Images downscaled to 256×256 (≈84 tokens each)

Hardware

  • 1× A100 80GB (us-central1-a)
  • bf16, gradient checkpointing, SDPA attention
  • Batch 1 × grad-accum 16 → effective batch 16
  • 3 epochs, ~20 hours

Benchmark setup

Models compared

  • Qwen2.5-VL-base — no finetune, zero-shot on our tasks
  • Ours (Qwen2.5-VL-LoRA) — MONITRS-finetuned
  • Gemini 3.1-flash-lite — proprietary baseline
  • GeoChat — remote-sensing VLM (single image, uses first frame) [running]
  • TEOChat — temporal remote-sensing VLM (multi-image) [running]

Evaluation

  • Same 13,937 test samples across all models (seed 42)
  • Test events never seen during training (event-level split)
  • MCQ metric: letter-match accuracy
  • Open-ended metrics: BLEU-1..4, METEOR, ROUGE-L (nltk + rouge-score)
  • Every model sees the same image count per sample; Qwen/TEOChat get full sequences, Gemini gets full sequences, GeoChat gets only the first image (arch limit)
